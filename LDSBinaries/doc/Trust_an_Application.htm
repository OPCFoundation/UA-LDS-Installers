Trusting a UA Application

The LDS must trust The need for an application to trust another application. Trust is established via PKI Certificates. Applications that do not trust each other can reject connections to each other depending upon the security methods used. an application (UA Server or Client) before it can be used.
Trusting an application in the LDS is a simple process, you can either:

  1. Manually copy the UA server certificate A PKI certificate for unique identification. These kinds of certificates are common on Websites, but can also be used to identify applications and people. to the trusted repository to trust the application.

  2. Try to connect (which will fail) and then look in the Rejected certificate repository and MOVE the applicable certificate file to the Trusted repository.

Normal Behavior, After Configuration

UA Servers should automatically register with the Local Discovery Server at start up and periodically re-register. The first time a Server registers with the LDS it will likely fail because it is not trusted; in this case execute step #2 above.

Once a certificate is trusted it will remain trusted until the administrator removes the trust. This means that the configuration will remain in-tact even after a reboot.
